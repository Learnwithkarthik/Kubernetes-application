# GKE API Gateway Demo - End-to-End

This document explains the complete process to expose a GKE application through Google Cloud API Gateway and demonstrate API key validation.

Architecture:

Client
→ API Gateway
→ API Key Validation
→ Cloud Run Proxy
→ GKE Ingress / Load Balancer
→ Kubernetes Service
→ Application Pod

---

## 4. Why We Cannot Use the Ingress IP Directly

Initially, using this in `x-google-backend`:

```yaml
address: http://8.233.43.127/users
```

results in an error similar to:

```text
Backend URL is forbidden:
cannot route requests by IP Address
```

API Gateway requires a hostname-based backend.

Because no custom DNS is being used in this demo, we create a small Cloud Run proxy.

Architecture becomes:

```text
API Gateway
     |
     v
Cloud Run Proxy
     |
     v
GKE Ingress IP
     |
     v
GKE Services
```

## 5. Create the Cloud Run Proxy

Create a directory:

```bash
mkdir api-proxy
cd api-proxy
```

Create:

```bash
vi app.py
```

Add:

```python
from flask import Flask, request, Response
import requests
import os

app = Flask(__name__)

BACKEND = "http://8.233.43.127"

@app.route("/", defaults={"path": ""}, methods=["GET", "POST", "PUT", "DELETE", "PATCH"])
@app.route("/<path:path>", methods=["GET", "POST", "PUT", "DELETE", "PATCH"])
def proxy(path):

    url = f"{BACKEND}/{path}"

    response = requests.request(
        method=request.method,
        url=url,
        headers={
            key: value
            for key, value in request.headers
            if key.lower() != "host"
        },
        data=request.get_data(),
        params=request.args,
        timeout=30
    )

    excluded_headers = [
        "content-encoding",
        "content-length",
        "transfer-encoding",
        "connection"
    ]

    headers = [
        (key, value)
        for key, value in response.headers.items()
        if key.lower() not in excluded_headers
    ]

    return Response(
        response.content,
        response.status_code,
        headers
    )


if __name__ == "__main__":
    app.run(
        host="0.0.0.0",
        port=int(os.environ.get("PORT", 8080))
    )
```

## 7. Create Dockerfile

```bash
vi Dockerfile
```

Add:

```dockerfile
FROM python:3.12-slim

WORKDIR /app

COPY requirements.txt .

RUN pip install --no-cache-dir -r requirements.txt

COPY app.py .

CMD exec gunicorn --bind :$PORT --workers 1 --threads 8 app:app
```

There is no need to manually build or push the container image.

Cloud Run source deployment automatically uses Cloud Build to create the image.

```bash
  --region us-central1 \
```

```text
Source Code
   |

   |
   v
Container Image
   |
   v
Artifact Registry
   |
   v

```

Get the Cloud Run URL:

```bash

  --region us-central1 \
  --format='value(status.url)'
```

## 11. Create API Gateway OpenAPI Configuration Without API Key

Create:

```bash

```

Add:

```yaml
swagger: "2.0"

info:
  title: student-portal-api
  description: Student Portal API Gateway Demo
  version: "1.0.0"

schemes:
- https

produces:
- application/json

paths:

  /users:
    get:
      operationId: getUsers
      x-google-backend:
        address: https://student-portal-proxy-xxxxxx-uc.a.run.app/users

        "200":
          description: Success
```

## 18. Create OpenAPI Configuration With API Key Enforcement

Create:

```bash
vi openapi-api-key.yaml
```

Add:

```yaml
swagger: "2.0"

info:
  title: student-portal-api
  description: Student Portal API Gateway Demo With API Key
  version: "2.0.0"

schemes:
- https

securityDefinitions:
  api_key:
    type: apiKey
    name: key
    in: query

security:
- api_key: []

paths:

  /users:
    get:
      operationId: getUsersWithKey
      x-google-backend:
        address: https://student-portal-proxy-xxxxxx-uc.a.run.app/users
      responses:
        "200":
          description: Success

  /courses:
    get:
      operationId: getCoursesWithKey
      x-google-backend:
        address: https://student-portal-proxy-xxxxxx-uc.a.run.app/courses
      responses:
        "200":
          description: Success

  /enrollments:
    get:
      operationId: getEnrollmentsWithKey
      x-google-backend:
        address: https://student-portal-proxy-xxxxxx-uc.a.run.app/enrollments
      responses:
        "200":
          description: Success
```

Important sections:

```yaml
securityDefinitions:
  api_key:
    type: apiKey
    name: key
    in: query
```

and:

```yaml
security:
- api_key: []
```

These tell API Gateway that an API key must be supplied.

# Key Concepts

**API**

A defined contract that allows one software application to communicate with another.

Examples:

```text
GET /users
GET /courses
POST /enrollments
```

**Ingress**

Routes incoming traffic to Kubernetes Services.

Example:

```text
/users → user-service
/courses → course-service
```

**API Gateway**

Controls how clients consume APIs.

In this demo it provides:

```text
API routing
API key validation
Central API entry point
```

**Cloud Run Proxy**

Used in this lab because API Gateway could not use the raw GKE Ingress IP directly as an `x-google-backend` address.

---

# Important Security Note

Never commit the real API key to GitHub.

Do not add commands like:

```text
export API_KEY="REAL_KEY"
```

with the actual value in your repository.

Use:

```text
export API_KEY='YOUR_API_KEY'
```

only as a placeholder in documentation.

API keys are suitable for demonstrating application/API consumer identification, but for real end-user authentication, JWT/OAuth-based authentication is generally more appropriate.

# Cleanup

When the demo is finished, remove the Gateway if you no longer need it:

```bash
gcloud api-gateway gateways delete student-portal-gateway \
  --location=us-central1
```

Delete API configs:

```bash
gcloud api-gateway api-configs delete student-portal-config-v2 \
  --api=student-portal-api

gcloud api-gateway api-configs delete student-portal-config-v1 \
  --api=student-portal-api
```

Delete the API:

```bash
gcloud api-gateway apis delete student-portal-api
```

Delete the Cloud Run proxy:

```bash
gcloud run services delete student-portal-proxy \
  --region=us-central1
```

This avoids leaving unnecessary billable resources running.
